# Autonomous supervisor

The repository supervisor closes the event gap between validation, independent Claude review, remediation, and merge-gate execution. It wakes when validation completes, a pull-request review is submitted, or a queued issue is labeled or reopened. An off-peak five-minute schedule remains the retry backstop, and the workflow can also be dispatched manually. It performs GitHub and Workspace Agent coordination only; it does not call Cloudflare, deploy code, modify secrets, access customer systems, or authorize production operations.

For each non-draft pull request, the supervisor waits for completed checks. Failed checks are routed to the Workspace Agent after a ten-minute fallback delay, giving the normal event dispatcher time to act first. Passing checks require an explicit Claude verdict bound to the exact head commit. Missing or inconclusive reviews cause at most three `@claude` requests: immediately, after ten minutes, and after another fifteen minutes. Fifteen minutes after the third unanswered request, the supervisor applies `autonomy-blocked` and dispatches the Workspace Agent with the stalled-review evidence. An exact-head rejection is dispatched for remediation. An exact-head acceptance is dispatched after the same ten-minute fallback delay to the existing merge gate, which must independently retrieve fresh evidence before merging.

HTML comment markers and deterministic Workspace Agent idempotency keys prevent repeated requests or duplicate merge/remediation dispatches for the same head and reason. A new commit creates a new exact-head review cycle.

Open issues labeled `autonomy-ready` form the task queue. The oldest eligible task is dispatched when no non-draft pull request is open. An issue labeled `autonomy-parallel` may be dispatched while pull requests are pending. Accepted dispatches receive `autonomy-dispatched`; that label records API acceptance, not completed work. The agent is instructed to link its implementation PR with `Closes #<issue>`. Only a trusted `OWNER`, `MEMBER`, or `COLLABORATOR` pull request with an exact same-repository closing reference or task-number branch counts as a link; untrusted fork contributors cannot pause the queue. A linked non-draft PR pauses task redispatch while normal PR supervision takes over; a linked draft pauses it only while the draft has activity within the fifteen-minute retry interval, preventing an abandoned draft from creating permanent limbo. If the issue remains open without active linked work or another dispatch marker, the supervisor retries after fifteen minutes with a fresh idempotency key, capped at three accepted attempts. At most one accepted Workspace Agent task trigger occurs per supervisor cycle, even if the later GitHub marker or label write fails. Fifteen minutes after the third accepted attempt, it applies `autonomy-blocked`, records the stall, and stops. A waiting retry does not starve another eligible queued issue. Issues labeled `security-review` or `major-decision` are held for owner authorization.

The supervisor creates the seven repository labels it uses if they do not already exist. It preserves existing label definitions except for one exact migration of the legacy `autonomy-dispatched` description from “completed” to “accepted,” correcting the prior false completion claim.

The workflow has only `actions: read`, `checks: read`, `contents: read`, `issues: write`, and `pull-requests: write`. It has no `contents: write` permission and therefore cannot modify code or merge directly. Clean-code merging remains the responsibility of the Workspace Agent under the owner's standing authorization and the repository's exact-head independent-review policy.

## Security stop and independent watchdog

Autonomous dispatch has a repository-native global kill switch. Any open issue labeled `autonomy-security-stop` makes the supervisor return before requesting review, modifying pull-request labels, or triggering a Workspace Agent. The supervisor also stops when an open pull request changes its workflow, the watchdog workflow, or either dispatch-boundary script. It creates a persistent security-stop issue that neither automation component can close. Only the repository owner may reactivate dispatch by reviewing the condition and closing the stop issue; a closure by any other account is treated as a new stop condition.

The separate `autonomy-watchdog` workflow checks the same protected paths and validates both workflows' permission boundary every five minutes and on relevant repository events. It has only `contents: read`, `pull-requests: read`, and `issues: write`. It receives no Workspace Agent identifier or token and invokes no dispatch endpoint, so compromise of the watchdog cannot authenticate an agent trigger, modify code, review a pull request, or merge. The supervisor and watchdog share a concurrency group so their repository mutations cannot overlap.

The stop is prospective: it blocks new dispatches and merge coordination after detection. It cannot revoke an already accepted Workspace Agent run. Consequently, exact-head review, bounded retries, least-privilege GitHub permissions, and the permanent prohibition on deployment, production, customer, secret, destructive, or permission-expanding operations remain required layers rather than relying on the watchdog alone.
